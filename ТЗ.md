# ТЗ: Симулятор «Звезда и планета» (версия 3)

## 0. Как пользоваться этим документом

Это техническое задание для ИИ-ассистента. Реализуй только то, что описано. Не добавляй функции, которых нет в ТЗ: несколько планет, пользовательские тела, воду, приливы, откат, графики, панели сверх указанных, импульсы по клавишам. Если пункт неоднозначен, выбери самый простой вариант и оставь комментарий в коде с описанием выбора.

Программа — учебная демонстрация. Цель: за 2 минуты показать, что автор понимает закон всемирного тяготения, второй закон Ньютона и закон сохранения энергии, и умеет объяснить, что меняется, когда на систему действует внешнее поле.

## 1. Что делает программа

В центре экрана находится неподвижная звезда. Вокруг неё по эллиптической орбите движется одна планета. Начальные параметры (размер звезды, размер планеты, начальное положение и вектор скорости) берутся из JSON-файла.

Пользователь может:
- зажать левую кнопку мыши (ЛКМ): в точке курсора включается гравитационное поле, которое притягивает планету;
- при зажатой ЛКМ крутить колёсико: меняется мощность поля;
- без ЛКМ крутить колёсико: меняется масштаб карты;
- перемещать карту правой кнопкой мыши (ПКМ) или стрелками;
- менять размер окна и переходить в полноэкранный режим;
- нажать R: вся система возвращается в начальное состояние из JSON.

Создавать свои тела нельзя. Импульсы по клавишам и кнопкам не предусмотрены.


```json
    "y": 0.0,
    "vx": 0.0,
    "vy": 1.1
  },
  "simulation": {
    "dt": 0.001,

  },
  "field": {
    "initialStrength": 0.0,
    "maxStrength": 5.0,
    "strengthStep": 0.1,
    "softening": 0.05
  },
  "camera": {
    "initialZoom": 200.0,
    "minZoom": 20.0,
    "maxZoom": 2000.0

    "width": 900,
    "height": 900,
```

Требования к файлу:

- **FR-C1.** Класс `SystemConfig` с вложенными классами `StarConfig`, `PlanetConfig`, `SimulationConfig`, `FieldConfig`, `CameraConfig`, `WindowConfig`. Имена полей совпадают с JSON.
- **FR-C2.** `ConfigLoader.Load(path)` читает файл из папки рядом с исполняемым файлом (`AppContext.BaseDirectory` + `config/system.json`). Путь собирается через `Path.Combine`.

- **FR-C4.** Значения проверяются: `radius > 0`, `mass > 0`, `gm > 0`, `dt > 0`, `minZoom < maxZoom`, `initialStrength` в диапазоне `[0, maxStrength]`. При нарушении выводится сообщение и программа завершается.
- **FR-C5.** Конфиг загружается один раз при старте. Кнопка R перезагружает значения из уже загруженного объекта, а не читает файл заново.
- **FR-C6.** Файл `config/system.json` копируется в папку сборки при каждом `dotnet build` (`CopyToOutputDirectory="PreserveNewest"`).

## 5. Физическая модель

### 5.1. Единицы

Безразмерные единицы. Все физические величины (`gm`, `mass`, `x`, `y`, `vx`, `vy`) берутся из конфига. Для отображения используется только масштаб камеры, он не влияет на физику.

### 5.2. Силы

На планету действуют две силы.

1. **Гравитация звезды, всегда:**
   ```
   a_star = −GM · r / |r|³,    r = (x, y)
   ```
   Закон всемирного тяготения и второй закон Ньютона. Звезда неподвижна в начале координат.

2. **Гравитация поля курсора, только при зажатой ЛКМ.** Центр поля — точка курсора `c = (cx, cy)` в мировых координатах, мощность `K` (`FieldStrength`):
   ```
   a_field = −K · (r − c) / (|r − c|² + ε²)^(3/2)
   ```
   `ε` — параметр смягчения (`softening` из конфига). Он не даёт ускорению уйти в бесконечность при очень близком подлёте. В комментарии указать, что это внешнее поле, а не сила звезды.

Итоговое ускорение: `a = a_star + a_field` (второй член учитывается только при включённом поле).

### 5.3. Мощность поля `K`

- Начальное значение берётся из `field.initialStrength`.
- Колёсико при зажатой ЛКМ меняет `K` на `±strengthStep`, в пределах `[0, maxStrength]`.
- При отпускании ЛКМ значение `K` сохраняется, но поле не действует.
- R возвращает `K` к `initialStrength`.

### 5.4. Интегратор: симплектический Эйлер (Эйлер–Кромер)

В каждом шаге `dt`:

1. Вычислить ускорение `(ax, ay)` по текущему положению и (если поле включено) по курсору.
2. Обновить скорость: `vx += ax·dt`, `vy += ay·dt`.
3. Обновить положение новой скоростью: `x += vx·dt`, `y += vy·dt`.

В комментарии одной фразой объяснить, что скорость обновляется раньше положения, и это помогает сохранять энергию на больших временах.

### 5.5. Энергия

- Кинетическая: `Ekin = m·(vx² + vy²) / 2`.
- Потенциальная от звезды: `Epot = −GM·m / r`.
- Полная: `E = Ekin + Epot`.

Энергия выводится на экран. Когда поле включено, `E` меняется, потому что поле внешнее и совершает над планетой работу. Это ожидаемое поведение, и его не нужно скрывать.

### 5.6. Падение на звезду

Если `r < star.radius + planet.radius`, планета считается упавшей. Программа:
- сбрасывает планету в начальные условия из конфига;
- очищает след;
- выводит надпись «Падение на звезду» на 2 секунды.

Других последствий нет.

## 6. Модуль `Physics/Planet.cs`

Класс `Planet` — единственный класс физики. Не знает о Raylib, окне и вводе.

Поля (`double`, публичные): `X`, `Y`, `VX`, `VY`, `Mass`.

Конструктор принимает все начальные значения.

Методы:

- `void Step(double dt, double gm, bool fieldOn, double cx, double cy, double k, double eps)` — один шаг по разделу 5.4.
- `double Radius()` — `sqrt(X² + Y²)`.
- `double Speed()` — `sqrt(VX² + VY²)`.
- `double KineticEnergy()` — по разделу 5.5.
- `double PotentialEnergy(double gm)` — по разделу 5.5.
- `double TotalEnergy(double gm)` — сумма.
- `void ResetTo(double x, double y, double vx, double vy)` — возвращает планету в заданное состояние.

Каждый метод имеет комментарий с названием закона или формулы.

## 7. Модуль `Physics/Checks.cs`

Статический класс `Checks`, метод `public static void RunEnergyCheck(SystemConfig config)`. Печатает проверку в консоль без графики.

Алгоритм:

1. Создать планету с начальными условиями из конфига.
2. Записать `E0 = TotalEnergy(gm)`.
3. Выполнять шаги, пока `t < 10 · 2π`. Поле выключено.
4. Каждые 1000 шагов печатать `t, x, y, E, (E − E0)/|E0|` с 6 знаками после запятой.
5. В конце печатать `max |E − E0| / |E0|`.
6. Вердикт: `OK`, если максимум меньше `0.001`, иначе `ПРЕВЫШЕНО`.

Если в конфиге параметры не дают `OK`, в комментарии указать, какой `dt` нужен для выполнения условия. Менять физику ради вердикта нельзя.

## 8. Окно, размер и полноэкранный режим

- **FR-W1.** Начальный размер окна берётся из `window.width` и `window.height`. Заголовок — из `window.title`.
- **FR-W2.** Окно можно менять мышью по краям (флаг resizable при создании окна, через `ConfigFlags`, в Raylib-cs соответствующий enum).
- **FR-W3.** Центр экрана (для формулы камеры) и размер кадра пересчитываются каждый кадр по текущим `GetScreenWidth()` и `GetScreenHeight()`. Физика и камера не сбрасываются при изменении размера.
- **FR-W4.** F11 переключает полноэкранный режим (`ToggleFullscreen()`). Повторное нажатие возвращает оконный режим с прежним размером.
- **FR-W5.** Минимальный размер окна — 400×400 пикселей. При меньших значениях окно не сжимается дальше (`SetWindowMinSize`).
- **FR-W6.** Сетка и текст перерисовываются под текущий размер окна без перезапуска.

## 9. Камера

Камера задаётся центром `(camX, camY)` в мировых координатах и масштабом `Zoom` в пикселях на единицу. Экранные координаты:

```
screenX = W/2 + (x − camX) · Zoom
screenY = H/2 − (y − camY) · Zoom
```

Ось Y экрана направлена вниз, поэтому знак минус.

- **FR-K1. Колёсико без ЛКМ:** масштабирование относительно точки под курсором (точка под курсором остаётся на месте). За один щелчок `Zoom *= 1.1` (вверх) или `Zoom /= 1.1` (вниз). Пределы: `camera.minZoom`…`camera.maxZoom`.
- **FR-K2. ПКМ зажата и движение мыши:** камера перемещается так, чтобы точка под курсором следовала за мышью.
- **FR-K3. Стрелки:** сдвиг камеры со скоростью, одинаковой на экране при любом масштабе: около 400 пикселей в секунду, переведённых в мировые единицы делением на `Zoom`.
- **FR-K4. Home:** возвращает камеру в `(0, 0)` и `Zoom = camera.initialZoom`. Камера при этом не влияет на физику.
- **FR-K5. R камеру не сбрасывает.** R сбрасывает только систему (раздел 11).

## 10. Гравитационное поле и визуализация

- **FR-F1.** ЛКМ зажата: `fieldOn = true`, центр поля — мировые координаты курсора.
- **FR-F2.** Колёсико при зажатой ЛКМ меняет `K` (раздел 5.3). В этом режиме колёсико не меняет масштаб.
- **FR-F3.** Визуализация поля: круг в точке курсора, радиус пропорционален `K` (в пикселях, например `K · 10`). Цвет фиолетовый, полупрозрачный. Если поле выключено, круг рисуется тонким контуром без заливки, чтобы было видно, где поле появится.
- **FR-F4.** Значение `K` выводится на экран текстом.

## 11. Сброс системы (клавиша R)

R возвращает всю систему в состояние из конфига:

- положение и скорость планеты (`planet.x`, `planet.y`, `planet.vx`, `planet.vy`);
- мощность поля `K` = `field.initialStrength`;
- время симуляции `t = 0`;
- след (очистка буфера);
- надпись «Падение на звезду», если она показывалась.

Камера, размер окна и полноэкранный режим при R не меняются.

Значения берутся из загруженного при старте `SystemConfig`. Файл при R не перечитывается (FR-C5).

## 12. Отрисовка

### 12.1. Фон и сетка

- Фон: тёмно-синий, `new Color(10, 12, 30, 255)`.
- **Сетка:** полупрозрачные белые линии, цвет `new Color(255, 255, 255, 40)` (альфа около 15 процентов). Прозрачность настраивается константой в коде.
- Сетка привязана к мировым координатам, то есть двигается и масштабируется вместе с картой.
- Шаг сетки в мировых единицах выбирается так, чтобы расстояние между линиями на экране было в пределах 50–150 пикселей. Шаг берётся из ряда 0.01, 0.02, 0.05, 0.1, 0.2, 0.5, 1, 2, 5, 10 и т. д., подходящий под текущий `Zoom`.
- Сетка покрывает весь видимый экран, включая края после изменения размера окна.
- Линия через начало координат (ось X и ось Y) может быть ярче остальных, но не обязательно.

### 12.2. Тела

- Звезда: жёлтый круг радиусом `star.radius` в мировых координатах, переведённый в пиксели через `Zoom`.
- Планета: голубой круг радиусом `planet.radius`.
- След: линия из последних 2000 положений планеты, серый цвет, прозрачность растёт к текущей точке. Буфер хранится в кольцевом массиве.
- Стрелка скорости (необязательно): зелёный отрезок от планеты в направлении скорости, длина пропорциональна `|v|`.

### 12.3. Текстовая панель (левый верхний угол)

Выводить строки:

```
t  = 12.345
r  = 1.0234
v  = 1.0812
E  = -0.4912
E0 = -0.4912
K  = 1.5 (ЛКМ — поле, колёсико при ЛКМ — мощность)
Масштаб: 200 px/ед.
```

Подсказка внизу экрана: «ЛКМ — поле, колёсико — масштаб или мощность, ПКМ/стрелки — камера, R — сброс, F11 — полный экран, Esc — выход».

### 12.4. Шрифт

- Загрузка `assets/DejaVuSans.ttf` через `Raylib.LoadFontEx` с набором кодовых точек: ASCII (32–126) и кириллица (0x0400–0x04FF).
- Вывод через `Raylib.DrawTextEx`.
- Если файла нет, использовать `Raylib.GetFontDefault()` и английские подписи.

## 13. Управление (сводка)

| Ввод | Действие |
|---|---|
| ЛКМ (зажата) | Включить гравитационное поле в точке курсора |
| Колёсико при зажатой ЛКМ | Мощность поля `K` ±0.1 |
| Колёсико без ЛКМ | Масштаб карты (к точке под курсором) |
| ПКМ (зажата) + движение | Перемещение камеры |
| Стрелки | Перемещение камеры |
| Home | Сброс камеры |
| R | Сброс системы по JSON |
| F11 | Полноэкранный режим и обратно |
| Esc | Выход |

Других клавиш и кнопок нет. Импульсы, клавиша пробела и кнопки добавления тел не используются.

## 14. Точка входа (`Program.cs`)

- Если аргументы содержат `--check`, загрузить конфиг и вызвать `Checks.RunEnergyCheck(config)`. Окно не открывать.
- Иначе: загрузить конфиг, создать окно (раздел 8), запустить главный цикл.
- Главный цикл на каждом кадре: обработать ввод, выполнить `stepsPerFrame` шагов `Step`, обновить след, отрисовать кадр.
- Симуляция идёт даже при включённом поле и при изменении размера окна.

## 15. Чего в версии нет

- несколько планет, пользовательские тела, добавление тел мышью;
- импульсы по клавишам или кнопкам (пробел и любые другие);
- водная оболочка, гидростатика, приливы;
- откат, история событий, сохранение состояния (кроме загрузки JSON);
- графики, CSV-лог, `report.txt`;
- столкновения тел, уничтожение (кроме падения на звезду из раздела 5.6);
- Runge–Kutta, Verlet, сравнение интеграторов;
- кроссплатформенная публикация, тесты xUnit.

## 16. Критерии приёмки

1. `dotnet run -- --check` выполняется без ошибок, печатает таблицу и вердикт `OK`.
2. Без поля полная энергия за 10 орбитальных периодов отклоняется меньше чем на 0,1 %.
3. `dotnet run` открывает окно, планета движется по эллиптической орбите, след виден.
4. Окно меняет размер мышью, физика и камера при этом не сбрасываются.
5. F11 переключает полноэкранный режим и возвращает оконный.
6. Полупрозрачная белая сетка видна, масштабируется вместе с картой, не мешает читать текст.
7. Колёсико без ЛКМ меняет масштаб относительно курсора в пределах `minZoom`…`maxZoom`.
8. ПКМ и стрелки двигают камеру.
9. ЛКМ включает поле в точке курсора. При отпускании поле выключается.
10. Колёсико при зажатой ЛКМ меняет `K` в пределах `[0, maxStrength]`, масштаб при этом не меняется.
11. R возвращает планету, `K`, время и след к значениям из `config/system.json`. Камера не сбрасывается.
12. Изменение `planet.vx`, `planet.vy`, `star.radius` или `planet.radius` в JSON и перезапуск меняют систему без правок кода.
13. Пробел и любые кнопки импульса ничего не делают: импульсов в программе нет.
14. Падение планеты на звезду сбрасывает систему и показывает надпись.
15. Файл `Physics/Planet.cs` не содержит `using Raylib_cs;` и не использует `System.Numerics.Vector2`.
16. При отсутствии `config/system.json` программа выводит понятное сообщение и завершается.
17. Все формулы в `Planet.cs` и `Checks.cs` снабжены комментарием с названием закона.

## 17. Порядок реализации (строго по шагам)

## 18. Требования к коду

- Один публичный класс на файл, имя файла совпадает с именем класса.
- Имена переменных и методов на английском, комментарии и сообщения пользователю на русском.
- Физические величины в `double`. В `float` переводить только при отрисовке.
- Состояние симуляции хранится в одном объекте. Глобальных изменяемых переменных вне него нет.
- Без `async`, потоков и LINQ в горячем цикле физики.
- Каждый метод физики короче 30 строк.

## 19. Что должен уметь объяснить автор на защите

1. Откуда формула `a_star = −GM·r/|r|³` (закон всемирного тяготения и второй закон Ньютона).
2. Почему в методе Эйлера–Кромера скорость обновляется раньше положения и почему это лучше сохраняет энергию.
3. Почему `E` почти постоянна без поля и меняется, когда поле включено (внешняя сила совершает работу).
4. Что такое `ε` (смягчение) и зачем оно нужно.
5. Почему R сбрасывает систему из JSON, а не из кода, и что даёт такая схема.
